## GOAL: UNIVERSAL LOSSLESS TOKENIZER v0.1

Implement a **Universal Lossless Tokenizer** as a *RIFT-instantiated representational control system*.

- Input: arbitrary byte streams
- Output: token IDs + side info sufficient for **bit-exact reconstruction**
- Tokenization is **streaming**, left-to-right, bounded lookahead
- Tokens correspond to **equilibrium attractors** of span latents
- Segmentation optimizes:

bit_cost + β·curvature_penalty + γ·stability_penalty

### RIFT instantiation mapping (for this repo)

This repository implements **RIFT-as-applied**, not RIFT-as-physical-field-theory. The required mechanics are:

1. **Carrier (MLR instantiation)**
 - Byte spans are mapped to latent states `z ∈ ℝ^d` via an encoder. The encoder is treated as the *measurement device* into representation space.

2. **Equilibrium (LoRE instantiation)**
 - Canonicalization is implemented as a **deterministic contraction mapping**:
   `z_{t+1} = (1−η) z_t + η F(z_t, span_features)` with fixed unroll steps.
 - A token is the ID of the attractor reached by equilibrium projection.

3. **Curvature / inconsistency (GRIT proxy)**
 - Curvature is implemented as a **local sensitivity / brittleness diagnostic** (Jacobian-norm / contraction deficit / Hutchinson-style estimators), not full Riemann curvature.
 - Curvature must correlate with unstable merges, token churn, or increased residual bpb.

4. **Dynamics / composition (DIRT instantiation)**
 - Dynamics are implemented as **streaming segmentation**: selecting span boundaries as a low-action path under the objective above.
 - Composition is admissible only if equilibrium remains stable and curvature remains bounded.

5. **Stability & survival (Curv Cycle)**
 - The system must enforce bounded curvature and stable operation under domain shifts.

### Harmonizer (required)

Implement a **Harmonizer** as the closed-loop control layer that keeps the tokenizer in a stable operating regime.

- The Harmonizer observes rolling statistics:
- `avg_token_len`, `bits_per_byte`, `residual_bpb`, `curvature_tail`, `stability_margin`, `token_churn`
- It adjusts admissibility/control parameters:
- `K_max`, `β_curv`, `γ_stab`, `max_span_len`, `split_merge_rate`
- It does **not** directly update encoder weights or codebook vectors; it regulates thresholds and penalties.

Conceptually:

S_t = {avg_token_len, bpb, curvature_tail, stability_margin, token_churn, …}
θ_t = {K_max, β_curv, γ_stab, max_span_len, split_merge_rate, …}
θ_{t+1} = clamp(θ_t + G(S_t − targets))

This is the operational Curv Cycle: representations persist and compose only if they can regulate their own curvature/stability under pressure.
